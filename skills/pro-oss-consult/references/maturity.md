# 성숙도 5단계

점수와 별개로 "지금 몇 단계이고, 다음 단계로 가려면 무엇부터"를 말한다.
**현재 단계의 빈칸을 먼저 채우고, 다음 단계의 선행 조건으로 넘어간다.** 단계를 건너뛰어
거버넌스부터 만드는 것은 안티패턴이다.

근거: Mattermost, Kubernetes, Rust, React, Django, Grafana, Supabase, Terraform, VS Code, ripgrep, bat.

| 단계 | 갖출 것 | 다음 단계로 가기 전에 (선행 조건) |
|---|---|---|
| **0 개인** | 명령 한 줄로 빌드·테스트, 기본 CI | **라이선스를 먼저 정한다.** 외부 기여가 쌓인 뒤 바꾸면 Terraform→OpenTofu처럼 포크가 난다 |
| **1 공개 가능** | 영어 README(가치 제안·설치·사용), 인식되는 LICENSE, About 설명·topics, semver 릴리스, CHANGELOG 또는 릴리스 노트, SECURITY.md(한 줄도 된다) | 릴리스 절차를 문서로 남긴다. 질문을 이슈 밖(Discussions)으로 뺀다. 의존성 봇을 켠다 |
| **2 기여 가능** | 실용적인 CONTRIBUTING(개발 환경·테스트·PR), yml 이슈 폼, 접두사 라벨 15~40개, 받아줄 일에만 `good first issue`, AI 기여 정책, ARCHITECTURE.md·확장 가이드 | 두 번째 메인테이너(한 사람 의존 해소), CODE_OF_CONDUCT, 첫 응답 시간 측정 |
| **3 커뮤니티** | 포럼·채팅, 공개 로드맵, 가벼운 RFC 절차, 트리아지 봇, 보안 지원 범위 명시, 문서 사이트 | 역할 사다리와 결정 규칙, LTS·폐기 정책, 상표·인프라 소유 주체 |
| **4 거버넌스** | GOVERNANCE.md, OWNERS 기반 권한, 정식 RFC(KEP·DEP), 재단·후원, 특정 회사 비중 제한 | |

## 판정 규칙

- 단계 N은 **단계 N의 "갖출 것" 중 M 항목이 전부** 있을 때 인정한다. 하나라도 비면 N-1이다.
- 사용자의 레포 대부분은 0~1단계다. 대표 레포의 현실적 목표는 2단계다. 3단계 이상은 실제 외부
  기여자가 생긴 뒤에 제안한다.
- `study` 성격은 단계를 매기지 않는다.

## 안티패턴 (보이면 지적한다)

- 기여자도 없는데 GOVERNANCE·RFC부터 만든다
- 봇 없이 라벨만 수십 개로 늘린다
- 건강 점수를 올리려고 빈 템플릿을 채운다
- `good first issue`를 붙여놓고 방치한다
- 규칙 공지 없이 stale 이슈를 일괄로 닫는다
- 외부 기여가 쌓인 뒤 라이선스를 바꾼다
- 이슈 트래커를 고객센터로 쓴다
- AI 생성 PR에 대한 방침이 없다
