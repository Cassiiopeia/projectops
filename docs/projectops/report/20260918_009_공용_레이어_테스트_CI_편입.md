# scripts/tests 11개 파일이 CI에서 한 번도 돌지 않아 깨진 테스트가 develop에 남아 있다

## 개요

`#611` 작업 중 전체 테스트를 돌렸더니 develop 에서 실패하는 테스트가 있었다. 그런데 **CI 는 초록불이었다.** `PROJECT-TEMPLATE-CI` 가 `.github/scripts/test/` 와 `skills/` 만 돌리고 `scripts/tests/` 를 경로 목록에서 빠뜨리고 있었기 때문이다. 그 폴더에는 3-layer 아키텍처의 **Layer 1(`scripts/common/`)** — 모든 스킬이 공유하는 도메인 로직 — 을 검사하는 파일이 11개 있다. 가장 널리 쓰이는 층이 가장 검증되지 않는 층이었다. CI 두 갈래에 편입하고, 실패하던 원인도 함께 해소했다.

## 변경 사항

### CI — 검사 항목을 빼지 않는다

- `.github/workflows/PROJECT-TEMPLATE-CI.yaml`
  - **빠른 길(`quick`)·넓은 길(`matrix-*`) 양쪽**에 `pytest scripts/tests/ -q` 추가. 한쪽만 넣으면 main 에서만 잡히거나 develop 에서만 잡힌다.

### 실패 원인 — 문서가 자기 규약을 어기고 있었다

- `skills/references/common-rules.md`
  - 참조 경로 전수 확인을 붙여넣기용 `python3 - <<'EOF'` 스니펫으로 적어 뒀는데, 같은 규약(§Python 행동 스크립트 표준)이 **heredoc 금지**를 정하고 있다. Windows Git Bash 에서 깨지고 한글 이스케이프가 망가지기 때문이다. `test_skill_docs.py` 가 정확히 이것을 잡았지만 그 테스트가 돌지 않아 아무도 몰랐다.
  - 스니펫을 지우고 테스트 실행 명령으로 교체했다.

### 손으로 돌리던 검사를 테스트로 승격

- `scripts/tests/test_skill_docs.py`
  - `test_skill_doc_reference_paths_exist` 신설. `references/` 접두사가 붙은 문서 참조 **78건**을 전수 확인한다.
  - 판정 대상을 좁혔다 — 디렉터리 접두사가 붙은 것만 본다. 맨 파일명(`impl.md`·`_release_notes.md`)은 임시 파일명이나 표 항목과 구분되지 않아 오탐이 났다. 문서의 원래 스니펫이 바로 이 오탐 때문에 2건을 잘못 보고했고, 아마 그래서 테스트로 승격되지 못한 채 남아 있었다.

## 주요 구현 내용

**`#543` 을 막으려고 적어 둔 검사가 실제로는 아무도 돌리지 않는 상태였다.** 그 이슈는 SKILL.md 에서 공용 문서를 `references/x.md` 로 가리켜(`../` 누락) 16개 스킬 50곳이 없는 경로를 지시했고, 이슈 생성 절차 문서를 못 찾아 중복 검사·승인 게이트를 건너뛴 사고였다. 검사를 문서에 적어 두는 것으로는 그것을 막지 못한다 — 테스트로 옮겨 CI 가 매번 돌리게 해야 막힌다.

**검증.** 고치기 전 `1 failed, 788 passed`, 고친 뒤 `792 passed`. `scripts/tests/` 단독으로 66건 통과. node 401건·마법사 3종 정합성도 함께 확인했다.

## 주의사항

**새 테스트가 실제로 잡는지 증명했다.** `pro-agent-test/SKILL.md` 의 `../references/common-rules.md` 에서 `../` 를 일부러 빼 `#543` 과 똑같은 실수를 심었고, 테스트가 실패하는 것을 확인한 뒤 원복했다.

**`#591` 이 같은 교훈이었다.** *"환경에 따라 건너뛰어지는 테스트는 안 돌아간 것과 구분이 안 된다. 초록불이 통과가 아니라 실행조차 안 된 것이었다."* 그때는 `local_only` 마커였고 이번에는 **CI 경로 목록에서 통째로 빠진 폴더**다. 같은 모양이 다른 자리에서 다시 났다. 앞으로 테스트 폴더를 새로 만들면 CI 경로에 넣었는지 반드시 확인해야 한다 — 지금 CI 가 도는 pytest 경로는 `.github/scripts/test/` · `skills/` · `scripts/tests/` 세 개다.

**`PROJECT-TEMPLATE-CI` 는 이 레포 전용이라 `project-types/common/` 미러가 없다.** 공통 워크플로우 수정 시의 두 곳 동기화 규칙은 적용되지 않는다 (확인 완료).
