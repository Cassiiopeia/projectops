# 템플릿 곳곳에 만든 사람의 실제 조직·앱 이름이 예시로 박혀 사용자 화면에 노출된다

## 개요

이 저장소는 **남의 프로젝트에 설치되는 템플릿**인데, 만든 사람이 실제로 쓰는 조직·앱 이름이 예시·주석·설정 기본값으로 11개 파일에 퍼져 있었다. 마법사 화면과 CLI `--help`, 그리고 **사용자 프로젝트에 생성되는 시나리오 파일 기본값**까지 닿았다. 기능을 깨뜨리지 않아 리뷰에서 걸리지 않고 오래 남았다.

전부 중립 예시(`acme-org`·`myapp`·`appdb`·`your-org`)로 바꾸고, 사용자에게 나가는 경로를 전수로 훑는 회귀 테스트를 붙였다.

## 주요 구현 내용

**새로 생길 이름까지 알아맞히는 검사는 만들 수 없다.** 그래서 현실적인 실수 하나만 겨냥했다 — **자기 프로젝트에서 예시를 복사해 붙이는 것.** 이름 목록을 테스트에 두고, 새 프로젝트를 시작하면 한 줄 추가하도록 주석으로 안내했다.

**검사 대상을 `git ls-files` 로 좁혔다.** 처음에는 디렉터리를 직접 훑었더니 `scripts/venv/` 안의 `site-packages` 까지 읽어 엉뚱한 곳(`pygments` 의 `qf1pElump`)에서 걸렸다. 추적되지 않는 것은 어차피 사용자에게 가지 않으므로 git 기준이 정확하고, 로컬 venv·캐시·빌드 산출물이 자동으로 빠진다.

**단어 경계를 뒀다.** 없으면 위의 `qf1pElump` 같은 부분일치가 걸린다.

**테스트·픽스처는 제외했다.** Cursor 설치 시 복사에서 빠지고(`SKIP_IN_COPY`), 실제 이름을 픽스처로 쓰는 것이 자연스럽다. `docs/` 와 `CHANGELOG` 도 제외 — 지난 일의 기록이라 고치면 이력이 틀어진다.

## 주의사항

**테스트가 실제로 잡는지 증명했다.** `pro-github/SKILL.md` 에 실제 조직명을 다시 심어 `SKILL.md:458` 을 정확히 짚어 실패하는 것을 확인한 뒤 원복했다.

**마법사 HTML은 줄맞춤이 깨질 수 있다.** 코드블록에서 콜론 뒤가 정렬돼 있어, 치환어의 글자 수를 원래와 같게 맞췄다. 바꾼 뒤 `check-consistency.py`·`test_wizard_cli.py` 를 돌려 통과를 확인했다.

**이 저장소 자신의 이름은 목록에 넣지 않았다.** `Cassiiopeia/projectops` 는 이슈 링크 등에 정당하게 쓰인다.

**기능에 영향을 준 것은 없다.** 전부 예시·주석·설정 기본값이었다. 다만 `wrangler.toml` 의 `ORG_NAME` 은 실제 설정 값이라, 그대로 두면 설치한 사람이 남의 조직을 가리킨 채 worker 를 올릴 수 있었다.
