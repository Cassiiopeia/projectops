🐛 문제 상황
---

`pro-github` 의 Actions 진단 서브커맨드 5개 중 **3개가 문서에 적힌 그대로 부르면 깨진다.**

```
actions show-run       Cassiiopeia projectops 35700287900  → OK
actions joblog         Cassiiopeia projectops 106656419974 → FAIL missing_argument
actions list-failed    Cassiiopeia projectops              → OK
actions resolve-pr     Cassiiopeia projectops 1            → FAIL missing_argument
actions resolve-branch Cassiiopeia projectops develop      → FAIL bad_args
```

특히 `joblog` 는 `show-run` 이 `next` 로 가리키는 **바로 다음 단계**다. SKILL.md 가 안내하는 진단 흐름(run 찾기 → 실패 job 확인 → **로그 읽기**)이 마지막 칸에서 끊긴다. 즉 **그 흐름을 끝까지 밟아 본 적이 없다.**

🔍 원인
---

`github_cli.py` 의 `actions` 파서가 선택 위치 인자를 **네 개 줄줄이** 두었다.

```python
p_ac.add_argument("run_id",    nargs="?", type=int)
p_ac.add_argument("job_id",    nargs="?", type=int)
p_ac.add_argument("pr_number", nargs="?", type=int)
p_ac.add_argument("branch",    nargs="?")
```

argparse 는 값을 **왼쪽부터** 채운다. 그래서 어떤 서브커맨드를 부르든 첫 값이 항상 `run_id` 로 들어간다.

| 부른 것 | 값이 들어간 곳 | 결과 |
|---|---|---|
| `joblog ... 106656419974` | `run_id` | `job_id` 가 비어 `missing_argument` |
| `resolve-pr ... 1` | `run_id` | `pr_number` 가 비어 `missing_argument` |
| `resolve-branch ... develop` | `run_id` (`type=int`) | `invalid int value: 'develop'` |

`show-run` 과 `list-failed` 만 **우연히** 맞는다 — 전자는 첫 칸이 제 자리이고 후자는 값이 없다.

형제 CLI 인 `pro-changelog-deploy` 의 `changelog_cli.py` 는 같은 서브커맨드 집합을 **위치 인자 하나(`arg`)** 로 받아 정상 동작한다. 한쪽만 네 개로 쪼개져 어긋난 것이다.

🛠️ 해결 방안
---

- `actions` 파서의 위치 인자를 **하나(`arg`)로 합친다.** 서브커맨드가 그 값을 해석한다 (`changelog_cli` 와 동일한 방식).
- 숫자가 필요한 서브커맨드는 파서가 아니라 **명령 안에서** 정수 변환하고, 실패하면 무엇이 잘못됐는지 알려준다.
- 회귀 방지: 다섯 서브커맨드를 **SKILL.md 에 적힌 형태 그대로** 불러 인자 해석이 맞는지 보는 테스트를 넣는다. 네트워크 없이 파싱만 검증한다.
