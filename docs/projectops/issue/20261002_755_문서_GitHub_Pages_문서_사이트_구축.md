📝 현재 문제점
---

- 프로젝트 문서가 GitHub 저장소 안의 md 파일(`docs/` 20여 개)로만 흩어져 있다. 검색, 목차, 탐색 구조가 없어 처음 온 사람은 README 한 장만 읽고 전체 모습을 파악하기 어렵다.
- README에 모든 것을 담으려다 길고 밋밋해졌다. 세부 내용이 들어갈 자리가 따로 없다.
- 영어, 중국어, 일본어 번역본이 README에만 있고, 상세 문서는 한국어뿐이다. 다국어를 확장할 구조가 없다.

🛠️ 해결 방안 / 제안 기능
---

- VitePress로 문서 사이트를 만들어 GitHub Pages(`https://cassiiopeia.github.io/projectops/`)로 배포한다.
- 기존 `docs/`를 단일 원본으로 사용한다(내용 복제 없음). 내부 작업 산출물(`docs/projectops`, `docs/superpowers` 등)은 사이트에서 제외한다.
- 랜딩 페이지, 시작하기, CLI, Skills, 워크플로우, 설정 순의 탐색 구조와 검색을 둔다. 한국어를 기본으로, 영어 핵심 페이지를 함께 제공하고 이후 중국어, 일본어로 확장할 수 있는 구조로 만든다.
- main push 때 사이트를 빌드해 배포하는 워크플로우를 추가한다. 이 레포 전용이라 사용자 프로젝트로 복사되지 않게 제외 목록에 등록한다.
- README는 짧고 시각적으로 줄이고, 상세는 사이트로 연결한다.

⚙️ 작업 내용
---

- `site/`: VitePress 설정, 랜딩, 탐색, 다국어 구조
- `.github/workflows/PROJECT-TEMPLATE-DOCS-DEPLOY.yaml`: 사이트 빌드와 Pages 배포
- `src/core/exclusions.js`, `.github/scripts/template_initializer.py`: `site/`, 배포 워크플로우 제외 등록
- 레포 설정: Pages 소스를 GitHub Actions로 지정
