🗒️ 설명
---

`pro-commit` 스킬은 커밋 직전 메시지 끝의 `@username` GitHub mention을 강제로 제거하는 안전망을 두고 있습니다. 이 스킬은 "커밋에 AI 흔적(`@claude` 등)을 절대 남기지 않는다"를 절대 규칙으로 삼고 있고, 이 sanitize 단계가 그 규칙의 **마지막 방어선**입니다.

그런데 이 단계에 쓰인 `sed` 구문이 **GNU sed 전용**이라 macOS(BSD sed)에서는 동작하지 않습니다. 더 나쁜 것은 **조용히 실패한다**는 점입니다. BSD sed는 라벨 구문을 인식하지 못해 오류를 내지만 종료 코드 0으로 통과하고, 입력을 **가공 없이 그대로 흘려보냅니다.**

결과적으로 macOS에서는 mention이 하나도 제거되지 않은 채 커밋됩니다. 안전망이 있다고 믿고 있지만 실제로는 꺼져 있는 상태입니다.

이 저장소의 agent 가이드에도 "macOS는 BSD 도구다, GNU 전용 옵션 금지"가 명시돼 있으나 이 지점이 누락됐습니다.

🔄 재현 방법
---

macOS에서 아래를 실행합니다.

1. 터미널에서 mention이 포함된 문자열을 sanitize 구문에 통과시킨다
2. 반환값을 확인한다

```
입력:  "테스트 메시지 @claude"
기대:  "테스트 메시지"
실제:  "테스트 메시지 @claude"   ← 제거되지 않음
종료코드: 0                      ← 실패인데 성공으로 보고됨
```

실제 커밋 흐름에서는 다음과 같이 드러납니다.

1. macOS에서 `/pro-commit`으로 커밋한다
2. 커밋 메시지 끝에 `@username` 형태의 mention이 포함돼 있었다면
3. 제거되지 않은 채 그대로 커밋된다

📸 참고 자료
---

**문제 지점**

| 항목 | 내용 |
|---|---|
| 파일 | `skills/pro-commit/SKILL.md` (6단계 커밋 실행) |
| 성격 | 셸 도구 이식성 문제 (GNU sed 전용 라벨 구문) |
| 증상 | macOS에서 mention 제거가 전혀 동작하지 않음 |
| 위험도 | 조용한 실패 — 종료 코드가 0이라 아무도 눈치채지 못함 |

**동작 차이**

| 환경 | sed 계열 | 결과 |
|---|---|---|
| Linux / Windows Git Bash | GNU sed | 정상 제거 |
| macOS | BSD sed | 제거 안 됨, 종료 코드 0 |

**같은 부류 문제 전수 조사 결과**

저장소 전체에서 GNU 전용 셸 옵션을 다시 훑은 결과, 현재 남아 있는 것은 이 한 곳뿐입니다. Flutter 마법사의 동기화 스크립트에는 이미 "GNU 전용 옵션 금지" 주석과 방어 코드가 들어가 있습니다.

✅ 예상 동작
---

- macOS, Linux, Windows 어디서 커밋하든 메시지 끝의 mention이 동일하게 제거되어야 합니다
- 셸 도구 구현 차이에 의존하지 않아야 합니다 (이 저장소는 이미 이런 로직을 파이썬 재사용 스크립트로 옮기는 표준을 두고 있습니다)
- 제거에 실패했다면 조용히 통과하지 말고 드러나야 합니다
