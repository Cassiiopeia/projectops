📝 현재 문제점
---

마법사 설치가 "성공"으로 끝나도, 그 결과물이 실제로 돌아가는 상태인지 확인하는 단계가 없다.
두 가지가 조용히 빠져나간다.

**1. 치환에 실패한 토큰이 그대로 남는다**

워크플로우 템플릿에는 설치 시 실제 값으로 바뀌어야 하는 토큰이 7종 있다.

```
__APPLICATION_YML_DIR__   __APPLICATION_YML_PATH__   __APP_ARTIFACT_NAME__
__DEPLOY_PORT__   __JAVA_VERSION__   __PROJECT_NAME__   __SERVICE_DOMAIN__
```

이 중 일부는 프로젝트 구조를 탐색해 자동으로 값을 만든다. 탐색이 실패하면(예: 설정 파일을
못 찾아 경로가 빈 문자열) 그 줄을 건드리지 않고 넘어가므로, 토큰이 남은 워크플로우가
**"설치 성공"으로 끝난다.** 문제는 배포를 돌릴 때에야 드러나고, 그때는 그 이름 그대로의
디렉터리가 만들어지는 식으로 엉뚱하게 실패한다.

**2. 등록해야 할 Secret이 안내되지 않는다**

설치된 워크플로우가 실제로 요구하는 값이 많다.

| Secret | 참조 횟수 |
|---|---|
| `DOCKERHUB_USERNAME` | 44 |
| `SERVER_PASSWORD` | 38 |
| `SERVER_HOST` | 27 |
| `SERVER_USER` | 24 |
| `ENV_FILE` | 23 |
| `SSH_KEY` | 20 |

설치 직후 상태로는 배포가 돌지 않는데 **그 사실이 어디에도 드러나지 않는다.** 정적 설치
가이드 문서는 복사되지만, 그 레포에 실제로 깔린 워크플로우 기준이 아니라서 "나에게 필요한
것"을 골라내지 못한다.

🛠️ 해결 방안 / 제안 기능
---

설치 직후 **디스크에 쓰인 최종 결과물을 다시 읽어** 검증하는 단계를 추가한다.
설치 전이 아니라 후인 이유는, 치환이 파일 단위로 흩어져 일어나고 자동 토큰은 탐색 결과에
의존하기 때문이다. 최종 내용을 보는 것이 실제 배포될 것과 같은 것을 보는 유일한 방법이다.

**검증 1 — 미치환 토큰 스캔**

남아 있는 토큰을 파일명·줄번호와 함께 보고한다. 두 가지는 검사에서 제외한다.

- **heredoc 구분자**(`__SUH_FILE_CONTENT_EOF__` 등): 값이 아니라 문법이므로 치환 대상이 아니다
- **주석으로 죽어 있는 줄**: 실행되지 않는다. 템플릿에는 선택 스텝이 통째로 주석 처리돼
  들어 있는데 이걸 세면 쓰지도 않는 값을 "등록하세요"라고 안내하게 된다

**검증 2 — 필요한 Secret 수집**

설치된 워크플로우를 훑어 요구하는 Secret 목록을 뽑고, 어느 파일이 쓰는지 함께 보여준다.
다음 둘은 목록에서 뺀다.

- **자동 주입값**(`GITHUB_TOKEN`): 사용자가 등록할 대상이 아니다
- **폴백이 있는 선택값**: 없어도 동작한다. 필수와 섞어 "등록해야 동작합니다"라고 하면
  안내 자체를 믿지 않게 된다

참조 구현(`project-auto-wizard`)의 해당 모듈은 86줄이며, 제외 패턴이 이 레포의 토큰 이름과
그대로 일치해 거의 수정 없이 이식 가능하다.

⚙️ 작업 내용
---

- 설치 후 검증 모듈 신설 (미치환 토큰 스캔 + 필요 Secret 수집)
- 통합 명령 흐름의 마지막 단계로 연결
- 완료 화면에 검증 결과 표시 (문제가 있을 때만 펼치고, 정상이면 한 줄로 압축)
- 선택 Secret 분류 기준을 이 레포 기준으로 정의
- 회귀 테스트 신설 (제외 규칙, 줄번호 정확도, 정렬)
