📝 현재 문제점
---

마법사 업데이트는 기존 워크플로우를 **신규 / 무변경 / 변경됨** 세 갈래로 나누고, "변경됨"에
대해 사용자에게 유지·백업·덮어쓰기를 묻는다. 그런데 이 "변경됨" 판정이 2-way 비교다.

```
지금 템플릿을 기본값으로 렌더한 결과 == 설치본 ?  →  같으면 무변경, 다르면 변경됨
```

**기준점(base)이 없다는 것이 문제다.** 업스트림이 한 글자만 고쳐도 판정 결과가 달라진다.

| 실제 상황 | 현재 판정 | 사용자가 겪는 일 |
|---|---|---|
| 사용자는 손 안 댐 + 템플릿이 개선됨 | **변경됨** | 매번 질문받음 |
| 사용자가 수정함 + 템플릿 그대로 | 변경됨 | 질문받음 (타당) |
| 사용자가 수정함 + 템플릿도 개선됨 | 변경됨 | 질문받음 (타당) |

첫 줄이 문제다. 템플릿이 개선될 때마다 **손대지도 않은 파일을 두고 판단을 요구**한다.
워크플로우가 10개면 10번 묻는다. 그래서 사용자는 결국 둘 중 하나를 하게 된다.

- 전부 유지 → 개선을 못 받는다
- 전부 덮어쓰기 → 자기 수정이 날아간다

정작 가려내야 할 **진짜 충돌**(내가 고친 파일을 업스트림도 고친 경우)이 나머지에 묻힌다.

🛠️ 해결 방안 / 제안 기능
---

**설치 시점의 기준점을 남긴다.** 파일별 해시를 기록해 두면 다음 업데이트에서 "누가 바꿨는지"를
가릴 수 있다.

**해시를 두 개 두는 이유**

환경값 치환으로 사용자 값이 들어간 파일은 디스크 내용과 "기본값으로 렌더한 결과"가 애초에
다르다. 하나로는 두 질문에 동시에 답할 수 없다.

| 해시 | 기록 내용 | 답하는 질문 |
|---|---|---|
| `installed` | 설치 시점 우리가 디스크에 실제로 쓴 내용 | 사용자가 그 뒤에 손댔는가 |
| `rendered` | 그 시점 템플릿을 기본값으로 렌더한 결과 | 업스트림이 그 뒤에 바뀌었는가 |

**개선되는 판정**

| 사용자 수정 | 업스트림 변경 | 처리 |
|---|---|---|
| 없음 | 있음 | **질문 없이 업데이트** ← 지금 매번 묻던 경우 |
| 없음 | 없음 | 무변경 |
| 있음 | 있음 | **질문** (진짜 충돌) |
| 있음 | 없음 | 사용자 수정 유지 |

**파일 사본이 아니라 해시만 남긴다.** 목적이 분류이지 자동 병합이 아니기 때문이다.

**기존 레포는 동작이 바뀌지 않는다.** 기준점 파일이 없으면 지금의 2-way 판정으로 폴백한다.
기준점은 다음 통합·업데이트 때 처음 생기고, 그 다음 업데이트부터 효력이 생긴다.

**부산물 — 삭제 감지**

기준점에는 있는데 디스크에 없는 파일은 사용자가 지운 것이다. 별도의 삭제 이력을 두지 않고도
"사용자가 의도적으로 제거한 워크플로우"를 알 수 있어, 업데이트가 그것을 되살리지 않게 된다.

⚙️ 작업 내용
---

- 기준점 기록·조회 모듈 신설 (해시 2종, 병합 기록, 손상 시 안전 폴백)
- 워크플로우 복사 분류에 기준점 기반 갈래 추가
- 복사 완료 후 기준점 기록 (실제로 쓴 파일만 `installed` 갱신)
- 대화형·비대화형 양쪽에서 새 갈래를 질문 없이 처리
- 기준점 파일을 통합 대상에서 제외(사용자 레포 산출물이지 템플릿 자산이 아님) 및 gitignore 검토
- 판정 진리표 회귀 테스트
