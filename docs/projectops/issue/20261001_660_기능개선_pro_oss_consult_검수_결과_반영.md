📝 현재 문제점
---

- pro-oss-consult(#644)를 출시 전에 8개 관점으로 검수한 결과, 그대로 배포하면 사용자에게 잘못된 안내가 나가거나 CLI가 부분 실패에 통째로 죽는 문제가 확인됐다.
- 설계: 수정 단계가 `/pro-github`에 없는 기능(About, topics, 라벨 CRUD, Discussions)을 쓰라고 안내하고, 자동 승인 모드가 레포 변경 승인까지 건너뛸 수 있다. 시작 전 질문이 SKILL.md에 없고, 트리거 문구가 pro-github와 겹치며 슬래시 명령이 `/oss-consult`로 틀려 있다.
- 코드: `local-facts`의 co_change가 한글 파일명을 8진수 이스케이프로 출력한다. 선택 엔드포인트(이슈 410, 릴리스·라벨 403) 하나만 실패해도 `collect` 전체가 죽는다. 타임아웃이 없고, 네트워크 오류와 rate limit에 `next`가 없으며 안내가 틀리다. 라벨·레포 목록 절단이 표시되지 않는다.
- 내용: SECURITY, CODE_OF_CONDUCT, AI 기여 정책을 자동 작성 대상으로 두어 연락처를 지어낼 위험이 있다. 성숙도 단계 표와 판정 규칙이 맞물리지 않는다. 영어 README, 앱 레포 "반드시" 목록, 스토어 요건이 표본 편향이거나 단정적이다.
- 검증 공백: collect, list-repos의 모킹 테스트와 한글 파일명 테스트가 없다.

🛠️ 해결 방안 / 제안 기능
---

- 검수 결과를 심각도 순으로 모두 반영한다. 사실 여부를 확인하지 못한 주장은 단정 문구를 빼고 공식 문서로 확인된 것만 남긴다.
- 자동 승인은 보고서 저장에만 적용하고 레포 변경은 항상 개별 승인으로 고정한다.
- 수정 단계는 실제 가능한 경로만 안내하고, 없는 기능은 서브커맨드로 추가하거나 제안 등급으로 내린다.
- CLI는 부분 실패를 `errors`로 흡수하고, 모든 오류에 `next`를 주며, 잘린 사실에는 표시를 붙인다.
- 실제 레포 실측, 공격자 관점, 기준선 스킬 비교, 신규 사용자 드라이런에서 나오는 결함도 같은 이슈에서 처리한다.
