🗒️ 설명
---

커밋과 배포 스킬은 실행 전에 사용자에게 결과물을 보여주고 승인을 받습니다. 그리고 "매번 확인받을지, 앞으로는 바로 진행할지"를 한 번 물어 기억해 둡니다. 사용자가 통제권을 갖되 반복해서 귀찮게 하지는 않는 구조입니다.

그런데 **파일을 만들어내는 다른 스킬 대부분에는 이 게이트가 없습니다.** 분석, 계획, 보고서, 테스트케이스 같은 스킬은 곧바로 산출물을 만들어 저장합니다. 내용이 마음에 들지 않으면 이미 만들어진 파일을 지우거나 덮어써야 합니다.

또한 이 스킬들은 **작업 범위를 묻지 않고 시작합니다.** 계획 스킬은 저장소 전체를 대상으로 할지 특정 모듈만 볼지 묻지 않고, 리뷰 스킬은 여섯 가지 관점을 항상 전부 적용하며, 테스트 스킬은 목표 커버리지를 묻지 않습니다. 사용자가 원하는 범위와 다르면 결과물 전체를 다시 만들어야 합니다.

같은 제품 안에서 어떤 스킬은 정중히 묻고 어떤 스킬은 묻지 않는 것은 일관성 문제이기도 합니다.

🔄 재현 방법
---

**승인 게이트가 없는 것**

1. 계획 스킬이나 보고서 스킬을 실행한다
2. 확인 절차 없이 곧바로 산출물이 만들어지고 저장된다
3. 방향이 다르면 만들어진 파일을 정리한 뒤 처음부터 다시 실행한다

**범위를 묻지 않는 것**

1. 규모가 큰 저장소에서 계획 스킬을 실행한다
2. 어느 범위를 다룰지 묻지 않고 전체를 대상으로 진행한다
3. 원하던 것이 특정 모듈이었다면 결과물을 통째로 버리게 된다

**스킬별로 물어보면 결과가 크게 달라지는 항목**

| 스킬 | 묻지 않아 생기는 문제 |
|---|---|
| 계획 / 구현 | 대상 범위가 어긋나면 결과물 전체를 폐기 |
| 리뷰 | 관점이 항상 고정이라 이번에 보고 싶은 부분에 집중 불가 |
| 테스트 / 테스트케이스 | 목표 수준과 기존 테스트 방식을 몰라 어긋난 결과 |
| 보고서 | 팀 내부용인지 클라이언트용인지에 따라 문체가 달라야 함 |
| 산출물 공통 | 저장 위치를 사용자가 정할 수 없음 |

✅ 예상 동작
---

- 파일을 만들어내는 스킬은 저장 전에 결과물을 보여주고 확인을 받아야 합니다
- "앞으로는 확인 없이 진행"을 한 번 선택하면 기억해 다시 묻지 않아야 합니다 (커밋·배포 스킬과 동일한 방식)
- 결과가 크게 달라지는 항목은 시작 전에 물어야 하며, 답이 명확한 상황에서는 묻지 않아야 합니다
- 질문 방식이 스킬마다 제각각이지 않고 한 가지 기준을 따라야 합니다
- 사용자에게는 자연어로만 안내하고 내부 설정 이름이나 파일 경로를 노출하지 않아야 합니다
