📝 현재 문제점
---

- pro-launch의 웹 안전 계약(`references/web.md`)이 "로그인 벽을 만나면 비밀번호를 타이핑하지 않는다. 사용자에게 넘긴다"로 고정돼 있어, 사용자가 원해도 에이전트가 입력을 거절한다.
- 사용자가 원격 세션에서 작업해 화면 앞에서 직접 키보드를 못 치는 경우가 잦은데, 거절로 끝나면 테스트가 막힌다.
- 같은 레포의 pro-agent-test는 "이메일·비밀번호까지는 네가 넣고 2단계 인증에서만 멈춘다"로 적혀 있어 두 스킬의 규칙이 서로 반대다.

🛠️ 해결 방안 / 제안 기능
---

- 로그인 벽을 만나면 거절하지 않고 사용자에게 묻는다: 계정·비밀번호를 알려주면 입력 / `--headed` 창에서 직접 로그인 / 이 단계는 건너뛰기.
- 사용자가 값을 주면 입력한다. 2단계 인증 코드도 사용자가 주면 넣는다.
- 안전장치는 유지한다: 값은 `--text-env`로만 전달, 틀려도 자동 재시도 금지, 파일·커밋·보고서·스크린샷·노트에 값 기록 금지, 끝난 뒤 변경 권고, 쿠키·토큰·`localStorage` 내보내기 금지, 결제 정보는 한 번 더 확인.
