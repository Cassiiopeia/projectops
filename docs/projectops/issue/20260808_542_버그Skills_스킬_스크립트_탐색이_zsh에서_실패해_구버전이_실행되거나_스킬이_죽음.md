🗒️ 설명
---

모든 스킬은 자기 파이썬 스크립트 위치를 찾을 때 아래 형태의 코드를 씁니다.

```
설치 경로 후보 여러 개를 한 번에 나열해서 그중 최신 것을 고른다
```

문제는 **후보 중 하나라도 존재하지 않으면 명령 전체가 무효가 된다**는 점입니다. Claude Code가 명령을 실행하는 셸은 zsh인데, zsh는 경로 패턴이 하나도 맞지 않으면 그 명령을 아예 실행하지 않고 중단합니다. 여러 후보를 한 줄에 나열했으므로, **Codex를 설치하지 않은 사용자**(대부분)에게는 Codex 후보가 매치되지 않아 **함께 나열된 Claude 경로까지 통째로 버려집니다.**

결과는 두 갈래입니다.

- **다른 설치본이 우연히 있는 경우** — 뒤이은 후보로 떨어져 **엉뚱한 사본**이 실행됩니다. 플러그인을 최신으로 올려도 계속 옛 버전이 동작하므로, 고친 내용이 반영되지 않고 사용자는 이유를 알 수 없습니다.
- **Claude Code만 설치한 경우** — 모든 후보가 같은 이유로 무효가 되어 **스킬이 "스크립트를 찾지 못했습니다"를 내고 종료**합니다. 스킬 자체를 쓸 수 없습니다.

실제로 다른 작업 세션에서 이 증상이 보고됐습니다. 플러그인이 최신인데도 구버전이 실행돼 최근 추가된 기능을 찾지 못했고, 사용자는 원인을 파악하지 못한 채 우회했습니다.

🔄 재현 방법
---

**A. 최신으로 올렸는데 구버전이 실행되는 경우**

1. 플러그인을 최신 버전으로 업데이트한다
2. 아무 스킬이나 실행해 스크립트 경로를 확인한다
3. 최신 설치본이 아니라 다른 위치의 오래된 사본이 선택된다

**B. 스킬이 아예 죽는 경우**

1. Claude Code만 설치된 환경을 준비한다 (다른 도구 설치본 없음)
2. 스킬 스크립트가 없는 일반 프로젝트에서 스킬을 호출한다
3. 경로 탐색이 빈 값을 반환하고 "스크립트를 찾지 못했습니다"로 종료된다

**실측 결과**

| 상황 | 기대 | 실제 |
|---|---|---|
| 최신 설치본 존재 | 최신 사본 사용 | 건너뛰고 오래된 사본 사용 |
| 최신 설치본만 존재 | 최신 사본 사용 | 아무것도 못 찾고 종료 |

📸 참고 자료
---

**원인**

여러 설치 위치 후보를 **한 줄에 나열**한 것이 원인입니다. 셸은 나열된 패턴 중 하나라도 맞지 않으면 그 명령을 실행하지 않습니다. 후보를 나열하는 방식 자체가 "일부는 없을 수 있다"는 전제와 맞지 않습니다.

**영향 범위**

| 항목 | 수치 |
|---|---|
| 이 방식을 쓰는 코드 위치 | 34곳 |
| 영향받는 스킬 | 스크립트를 쓰는 전 스킬 |
| 영향받는 셸 | zsh (Claude Code 기본 실행 셸) |

**부가 문제 — 우선순위 없음**

후보들을 한꺼번에 모아 정렬 후 마지막 하나를 고르는데, 정렬 기준이 경로 문자열이라 **설치 위치가 다르면 버전이 낮은 쪽이 뒤에 와서 선택**될 수 있습니다. 실측에서 최신 4.2.44 대신 4.2.19가 선택됐습니다.

✅ 예상 동작
---

- 설치 위치 후보 중 일부가 없어도 **나머지 후보를 정상적으로 검사**해야 합니다
- 여러 곳에 설치본이 있으면 **정해진 우선순위**대로 선택해야 하며, 우연한 정렬 순서에 좌우되면 안 됩니다
- 같은 위치에 여러 버전이 있으면 **가장 최신 버전**을 골라야 합니다
- zsh와 bash 어디서 실행해도 같은 결과가 나와야 합니다
- 이 저장소에서 개발 중이면 지금처럼 로컬 코드가 우선이어야 합니다
