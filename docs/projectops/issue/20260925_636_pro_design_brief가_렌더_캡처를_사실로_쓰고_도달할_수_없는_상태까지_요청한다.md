📝 현재 문제점
---

2026-09-25 elum에서 `pro-design-brief` 방식으로 디자인 요청 8건(#419~#427)을 올린 뒤 실기기로 다시 밟았더니, 요청서가 틀린 주장을 담고 있었다 (#634 댓글 두 개).

- **도달할 수 없는 상태를 요청했다** (#424). 스펙 문장("보상 이모지는 임시")을 현재 동작으로 믿었고, 가짜 데이터에 지금은 만들 수 없는 옛 값을 넣어 나오지 않는 화면을 찍었다.
- **위젯 렌더 캡처를 사실로 썼다.** 렌더만 보고 쓴 주장 7건이 실기기와 달랐다.

| 렌더에서 본 것 | 실기기 | 왜 달랐나 |
|---|---|---|
| 시트 뒤 저장 버튼이 비쳐 둘로 보임 | 뒤 화면을 어둡게 가림 | 렌더 하네스에 모달 가림막이 안 그려짐 |
| 오류 코드가 두 줄로 갈라짐 | 한 덩어리 (대신 문구 중복) | 가짜 실패 객체가 실제 실패와 모양이 다름 |
| 오늘 일과 실패 화면 | 오프라인이면 기기 저장본 표시 | 오프라인 우선 경로를 가짜 provider 가 건너뜀 |
| 실패 화면이 바로 뜸 | 약 40초 로딩 뒤 뜸 | 가짜는 즉시 실패, 실제는 자동 재시도 |
| 팝업 한 글자 줄바꿈 | 한 줄 | 렌더 폭 ≠ 기기 폭 |
| 주간 100개 | 운영 설정 50개 | 테스트 픽스처 값을 사실로 씀 |
| 보이는 곳 6군데 | 7군데 | 서버가 내려주는 공지는 코드 검색에 안 걸림 |

- 반대로 **실기기에서만 나온 결함 3건**은 렌더로는 안 보였다.
- `copy-lint --banned "아이"` 가 `아이콘` 에 걸린다 (금지어를 부분 문자열로 찾는다).
- 게시 뒤 틀린 것을 발견했을 때 무엇을 해야 하는지 절차가 없다.

🛠️ 해결 방안 / 제안 기능
---

- **상태 연출은 렌더, 사실 주장은 실기기.** "지금 앱은 이렇다" 는 문장마다 실기기·운영 API·코드 근거를 붙이고, 렌더 근거만 있는 주장은 게시 전에 걸러 낸다.
- **보드에 캡처 출처를 표시한다** — `렌더(가짜 데이터)` · `실기기` · `운영 서버` · `시안`. 표시 없는 캡처는 경고.
- **상태마다 도달 가능성을 적는다** — 지금 흐름에서 나온다 / 예전 데이터에만 나온다 / 확인 못 함.
- 수치는 픽스처가 아니라 운영 API·설정에서 읽고, 서버가 내려주는 문구(공지·약관)도 상태 목록에 넣는다.
- 금지어는 낱말 단위로 본다 (조사가 붙은 것은 잡고, 다른 낱말의 일부는 잡지 않는다).
- 게시 뒤 틀린 것을 발견하면 본문을 고치고 정정 댓글을 단다.
