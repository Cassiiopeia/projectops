🗒️ 설명
---

분석, 계획, 보고서 등 md 산출물을 만드는 스킬이 8종 있습니다. 이들이 저장 위치를 정하는 방식에 두 가지 문제가 있습니다.

**첫째, 경로가 고정입니다.** 모든 산출물이 `docs/projectops/` 아래로만 저장됩니다. "우리 팀은 산출물을 다른 폴더에 모은다"거나 "이 저장소에는 문서를 두고 싶지 않다" 같은 요구를 받아줄 방법이 없습니다. 다른 설정들(담당자, 승인 방식, 릴리스 브랜치 등)은 모두 사용자별로 조정 가능한데 산출물 경로만 예외입니다.

**둘째, 절반의 스킬은 경로를 계산할 수단조차 없습니다.** 산출물 경로 규칙 문서가 스스로 이렇게 적어두고 있습니다.

> 나머지(analyze, plan, design-analyze, refactor-analyze, ppt) — 해당 skill 자체 cli 없음, agent가 직접 경로 계산하거나 report_cli 임시 사용

즉 5개 스킬은 "알아서 계산하거나 남의 것을 빌려 쓰라"는 상태입니다. 규칙이 코드로 강제되지 않으니 스킬마다 파일명 규칙이 갈라질 수 있고, 실제로 갈라져도 아무도 알아채지 못합니다.

🔄 재현 방법
---

**경로 변경이 불가능한 것**

1. 산출물을 다른 폴더에 저장하고 싶어 설정을 찾는다
2. 어떤 설정에도 산출물 경로 항목이 없다
3. 스킬 문서를 직접 고치는 것 외에 방법이 없다

**경로 계산 수단이 없는 것**

1. 계획 스킬로 산출물을 만든다
2. 스킬이 경로를 직접 계산하거나 다른 스킬의 도구를 빌려 쓴다
3. 보고서 스킬이 만든 파일명 규칙과 미세하게 달라져도 검증하는 곳이 없다

📸 참고 자료
---

**산출물 생성 스킬과 경로 계산 수단 보유 현황**

| 스킬 | 자체 경로 계산 수단 |
|---|---|
| pro-review | 있음 |
| pro-troubleshoot | 있음 |
| pro-report | 있음 |
| pro-analyze | **없음** |
| pro-plan | **없음** |
| pro-design-analyze | **없음** |
| pro-refactor-analyze | **없음** |
| pro-ppt | **없음** |

**설정 가능 항목 비교**

| 항목 | 사용자가 바꿀 수 있나 |
|---|---|
| 이슈 담당자 | 가능 |
| 커밋 승인 방식 | 가능 |
| 릴리스 브랜치 | 가능 |
| 릴리스 노트 생성 방식 | 가능 |
| **산출물 저장 경로** | **불가능** |

✅ 예상 동작
---

- 산출물을 만드는 8개 스킬 **모두** 동일한 방식으로 경로를 계산할 수 있어야 합니다
- 저장 위치를 사용자가 설정으로 바꿀 수 있어야 하며, 설정하지 않으면 지금과 똑같이 동작해야 합니다
- 경로 규칙이 문서로만 존재하지 않고 코드로 강제되어야 합니다
- 어떤 스킬이 만들었든 파일명 규칙이 동일해야 합니다
