📝 현재 문제점
---

릴리스 PR(develop→main)에는 체인지로그가 자동으로 붙지만, **일상적인 작업 PR에는 아무
요약도 없다.** 리뷰어는 커밋 목록과 변경 파일을 직접 훑어야 무엇이 바뀌었는지 파악할 수 있다.

CodeRabbit을 쓰는 레포는 그 봇이 요약을 달아주지만, **CodeRabbit을 쓰지 않는 레포는 대안이
없다.** 이 템플릿은 이미 릴리스 노트를 만들기 위한 provider 사다리(선택 provider →
GitHub Models → 커밋 분석)를 갖추고 있는데, 그 능력이 릴리스 시점에만 쓰이고 있다.

또한 이 레포는 **"이 변경이 어디로 가는지"를 구분할 수단이 없다.** 앱스토어·플레이스토어
심사로 이어지는 레포인지 여부는 현재 스킬 설정 파일(사용자 홈)에만 있어서, 워크플로우는 그
값을 볼 수 없다. 같은 사실이 두 곳에 따로 존재하면 언젠가 어긋난다.

🛠️ 해결 방안 / 제안 기능
---

**1. 일반 PR에 AI 요약 댓글**

기본 브랜치를 향하는 PR이 열리거나 갱신되면 요약을 만들어 댓글로 단다.

- **기존 provider 사다리를 그대로 재사용한다.** 커밋 범위를 환경변수로 받는 구조라 릴리스
  노트 생성기와 같은 엔진을 쓸 수 있다. 별도 생성기를 만들면 두 경로가 갈라져 드리프트가 난다.
- API 키가 없어도 동작한다 — GitHub Models(무료) → 커밋 분석 순으로 폴백한다.
- **릴리스 PR에는 달지 않는다.** 체인지로그가 이미 그 일을 한다.
- 외부 저장소에서 온 PR(fork)에는 달지 않는다.

**2. 댓글은 쌓지 않고 갱신한다**

PR에 커밋을 추가할 때마다 새 댓글이 달리면 스레드가 요약으로 도배된다. 식별용 표식을 댓글에
심어 두고, 다음 실행에서 그 댓글을 찾아 **내용만 교체**한다.

**3. 프로젝트 성격을 version.yml로 올린다**

앱 심사로 이어지는 레포인지를 `version.yml`의 옵션으로 기록해 **워크플로우와 스킬이 같은
값을 보게 한다.** 그 값이 켜져 있으면 PR 요약 상단에 "이 변경은 다음 릴리스에서 스토어
심사로 이어진다"는 안내를 덧붙여, 리뷰어가 무게를 다르게 잡을 수 있게 한다.

기존 레포는 키가 없으므로 안내가 붙지 않는다(현행 유지).

⚙️ 작업 내용
---

- AI PR 요약 워크플로우 신설 (루트와 공통 원본 두 곳 동일 유지)
- provider 사다리에 커밋 범위를 넘겨 재사용, 실패해도 PR을 막지 않도록 처리
- 표식 기반 댓글 갱신 (신규 작성 / 기존 갱신 분기)
- `version.yml` 옵션에 프로젝트 성격 추가 — 마법사 파싱·기록, 통합 시 보존
- 요약 상단 안내 분기
- 워크플로우 트리거·분기 조건 회귀 테스트
