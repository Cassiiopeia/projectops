📝 현재 문제점
---

템플릿을 새 레포에 통합하면 사용자는 가장 먼저 **Personal Access Token을 만들어
`_GITHUB_PAT_TOKEN`으로 등록**해야 한다. 완료 화면의 "다음 3가지 작업" 중 1번이 이것이다.
토큰 생성 → 권한 선택 → Secret 등록까지 거쳐야 릴리스가 돌기 시작하므로, 도입 첫 경험에서
가장 큰 마찰이다.

그런데 실제 코드를 보면 **PAT가 꼭 필요한 곳과 아닌 곳이 섞여 있다.**

| 위치 | 현재 | 실제로 PAT가 필요한가 |
|---|---|---|
| PR 본문 초기화 / 제목 변경 (3곳) | PAT | 아니오 — `pull-requests: write` 권한이면 기본 토큰으로 가능 |
| CodeRabbit Summary 요청 댓글 | PAT | 아니오 |
| 릴리스 노트 생성 (2곳) | PAT | 아니오 |
| 저장소 체크아웃 / PR 브랜치 최신화 | PAT | 아니오 |
| **자동 PR Merge** | 기본 토큰 1차 → PAT 2차 | **이미 폴백 구조** |
| **머지 후 후속 워크플로우 트리거** | PAT 머지에 의존 | **예 — 여기가 진짜 제약** |

즉 머지 자체는 이미 기본 토큰으로 시도하고, PAT는 보호 규칙 우회용 2차 폴백일 뿐이다.
나머지 8곳은 **PAT가 없으면 빈 문자열로 인증을 시도해 실패**한다.

**진짜 제약은 후속 트리거다.** GitHub은 기본 토큰이 만든 push로는 워크플로우를 다시
트리거하지 않는다(무한 루프 방지). 그래서 PAT 없이 머지하면 릴리스는 되지만 그 뒤에
따라와야 할 배포·동기화 워크플로우가 돌지 않는다.

🛠️ 해결 방안 / 제안 기능
---

**PAT를 필수에서 선택으로 내린다.** 없으면 없는 대로 완주하고, 있으면 더 매끄럽게 동작한다.

**1. 인증 폴백**

PAT를 쓰는 8곳을 "PAT가 있으면 PAT, 없으면 기본 토큰"으로 바꾼다. 워크플로우 표현식이
빈 값을 falsy로 처리하므로 한 줄로 표현된다. 권한은 `permissions` 블록으로 이미 확보돼 있다.

**2. 후속 워크플로우 명시 트리거**

기본 토큰으로 머지했으면 후속이 자동으로 돌지 않으므로, 머지 성공 직후 **직접 깨운다.**
`workflow_dispatch` 이벤트는 기본 토큰으로도 트리거할 수 있다는 점을 이용한다.

대상은 고정 목록이 아니라 **레포에 실제로 설치된 워크플로우에서 동적으로 찾는다** —
프로젝트 타입마다 배포 워크플로우가 다르기 때문이다. 조건은 두 가지다.

- 기본 브랜치 push로 트리거되는가 (그래야 원래 돌았어야 할 대상이다)
- `workflow_dispatch`를 지원하는가 (없으면 깨울 수단이 없다)

PAT로 머지한 경우에는 push가 정상 트리거하므로 **이 단계를 건너뛴다** (중복 실행 방지).

**3. 깨울 수 없는 워크플로우 안내**

`workflow_dispatch`가 없는 워크플로우는 트리거할 방법이 없다. 이 경우 경고로 이름을
알려 사용자가 판단하게 한다. 템플릿이 제공하는 워크플로우 중 해당하는 것은
`PROJECT-COMMON-README-VERSION-UPDATE` 하나이므로, 여기에 `workflow_dispatch`를 추가한다.

**4. 안내 문구 조정**

완료 화면과 문서에서 PAT를 "필수 1번 작업"이 아니라 "선택 — 등록하면 후속 자동화가 더
매끄러워집니다"로 바꾼다. 설치 후 검증(#549)의 선택 Secret 분류에도 `_GITHUB_PAT_TOKEN`을
추가한다.

⚙️ 작업 내용
---

- 릴리스 워크플로우의 PAT 참조 8곳을 기본 토큰 폴백으로 전환 (루트·common 두 곳 동일 유지)
- 머지 후 후속 워크플로우 동적 탐색·트리거 단계 추가 (PAT 없이 머지한 경우에만)
- 탐색·트리거 로직을 재사용 스크립트로 분리하고 통합 복사 목록에 추가
- `PROJECT-COMMON-README-VERSION-UPDATE`에 `workflow_dispatch` 추가
- 설치 후 검증의 선택 Secret 목록에 `_GITHUB_PAT_TOKEN` 편입
- 완료 화면·문서의 PAT 안내를 필수에서 선택으로 조정
- 탐색 규칙 회귀 테스트 신설
