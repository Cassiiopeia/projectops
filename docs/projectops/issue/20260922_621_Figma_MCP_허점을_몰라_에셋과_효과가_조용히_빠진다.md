📝 현재 문제점
---

`pro-figma-verify` 가 값은 세지만, **Figma MCP 응답이 실제로 어떻게 생겼는지를 모르는 채로** 세고 있었다. 실제 파일(노드 2,617개)과 화면 하나를 끝까지 밟아 보니 아래가 전부 그대로 빠져나갔다.

**세는 쪽**

- **한 문자열 안에 그림자가 여러 줄** 들어온다. 정의 12개가 실제로는 그림자 16줄이었고, 도구는 12줄로 셌다. 네 줄짜리 효과에서 안쪽 세 줄이 빠져도 개수가 안 변한다. 이것이 원래 사고의 그 값이다.
- 효과가 layout 수천 줄 사이에 섞여 **묻힌다.** 한 화면이 `layout 3,294 / fills 1,849 / effects 171` 이라 효과는 3%인데, 빠뜨리는 것은 거의 항상 이쪽이다.
- 종류 구분이 없어 **안쪽 그림자, 글로우, 블러, 배경 블러**가 전부 "효과" 한 덩어리로 보인다.
- 스타일 키가 `fill_5PQ06X` 만 오는 게 아니라 `Label Color/Light/Primary` 처럼 사람이 붙인 이름도 섞여 온다.

**에셋 (아예 다루지 않고 있었다)**

- 덤프에 `IMAGE-SVG` 가 609개인데 스킬에 다운로드 이야기가 한 줄도 없었다. 값을 다 옮겨도 화면에 아이콘이 없다.
- 덤프에는 **아이콘의 모양 정보가 없다.** 그래서 이름으로 묶으면 위험하다. Figma 기본 이름 `Vector` 71개가 실제로는 서로 다른 48종이었다.
- `fileName` 이 `^[a-zA-Z0-9_.-]+\.(png|svg)$` 만 받는데 에셋 609개 중 **281개(46%)** 가 한글, 공백, 슬래시를 담은 이름이라 그대로 넘기면 거부된다.
- 609개 중 **592개**가 45종 이름에 몰려 있어 이름으로 저장하면 서로 덮어쓴다.
- `imageRef` 도 참조 뒤에 있어 안 풀면 사진 에셋을 통째로 놓친다.
- 효과가 붙은 에셋은 번짐이 SVG 필터로 박혀 와서 **받은 그림이 더 크다.** layout 36x34 인 글로우 도형이 96x94 로 왔다. 모르면 도형이 쪼그라들거나 효과가 두 번 적용된다.

**호출 자체**

- 스킬에 MCP 호출법이 없었다.
- 링크의 `node-id` 가 화면이라는 보장이 없다. 실제로 그것이 SECTION 이라 `nodeId` 를 주고도 1,083,214자가 왔다.
- `localPath` 는 프로젝트 안이어야 한다. 밖을 주면 `Directory traversal is not allowed` 로 거부된다.

🛠️ 해결 방안 / 제안 기능
---

- 괄호 깊이를 세어 그림자 문자열을 **줄마다 쪼갠다** (`rgba(...)` 안의 쉼표는 건드리지 않는다).
- 효과에 **종류 이름**을 붙이고(그림자, 안쪽 그림자, 글로우, 블러, 배경 블러) `coverage` 출력에서 **따로 꺼낸다.**
- `assets` 서브커맨드를 새로 만들어, 내려받을 목록과 `download_figma_images` 에 그대로 넣을 `nodes[]` 를 만들어 준다.
- 묶는 기준을 **증거 있는 것만**으로 한다. `componentId` 가 같으면 확실, 노드 내용이 같으면 추정, 이름만 같으면 안 묶는다.
- 통과하는 파일명을 만들고, 겹치면 번호를 붙이고, 뜻을 잃은 이름은 표시해 사람이 다시 짓게 한다.
- 덤프가 알려주는 `imageDownloadArguments` 를 그대로 쓴다.
- 효과가 박혀 크게 올 에셋을 미리 짚어 준다.
- 참조 해소를 **키 일치**로 판별해 사람이 붙인 이름도 풀리게 한다.
