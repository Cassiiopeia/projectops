📝 현재 문제점
---

릴리스 파이프라인이 버전을 올릴 때 **커밋 내용과 무관하게 항상 patch만 증가**시킨다.
`PROJECT-COMMON-RELEASE-CHANGELOG` 워크플로우의 버전 확정 단계가 `version_manager`의
patch 증가 명령 하나만 호출하는 구조라, major/minor는 사람이 `version.yml`을 직접
고쳐야만 올라간다.

**실측 결과**

- `origin/main` 릴리스 이력 **45회가 전부 patch** → 현재 `4.2.45`
- 그 구간에 기능 추가(`feat`) 커밋이 분명히 있었는데도 **minor는 45번 중 0번** 증가
- 즉 "minor를 올려야 한다"는 판단을 사람이 매번 기억해야 하는데, 45번 연속 실패했다

버전 숫자만 보고 변화의 성격(호환성 깨짐/기능 추가/버그 수정)을 판단한다는 시맨틱
버저닝의 목적이 사실상 죽어 있다. 이 템플릿을 쓰는 모든 레포가 같은 상태다.

참고로 빌드 번호(`version_code`)는 매 릴리스 +1이 맞고, 이번 개선의 대상이 아니다.

🛠️ 해결 방안 / 제안 기능
---

릴리스 구간의 **커밋 제목 규칙**으로 승격 폭(major/minor/patch)을 결정하도록 바꾼다.
판정은 전부 결정적이며 AI를 쓰지 않는다 — 같은 커밋이면 언제나 같은 버전이 나온다.

**판정 규칙**

| 커밋 형태 | 판정 |
|---|---|
| `제목 : feat! : 내용` (projectops 컨벤션 + breaking 마커, 신설) | major |
| `feat!:` / `fix(api)!:` (Conventional Commits) | major |
| `제목 : feat : 내용` / `feat: 내용` | minor |
| fix, docs, chore, refactor, test, 자유형식, 미분류 | patch |
| `[skip ci]` 포함, `Merge`로 시작, 빈 줄 | 판정 제외 |

한 구간에 섞이면 가장 높은 것이 이긴다 (major > minor > patch).

**하위호환 — 기존 레포는 동작이 바뀌지 않는다**

`version.yml`의 옵션(`semver_auto`)으로 제어한다.

| 상태 | 동작 |
|---|---|
| 키 없음 (이미 통합된 레포 전부) | patch 고정 — 현행 유지 |
| 켜짐 | 규칙 승격 |
| 꺼짐 | patch 고정 |

신규 통합 시에만 켜진 상태로 기록한다. 이미 운영 중인 레포(RomRom-BE/FE 등)의
버전이 예고 없이 튀지 않게 하는 것이 이 기본값의 목적이며, 기존 레포는 사용자가
직접 켜야 바뀐다.

**안전망 워크플로우(`PROJECT-COMMON-VERSION-CONTROL`)는 건드리지 않는다.**
릴리스 PR을 거치지 않은 main 직접 push에만 발동하는 비권장 경로라 커밋의 컨벤션
준수를 신뢰할 수 없다. 현행대로 patch를 유지한다.

**참조 구현과의 차이**

`project-auto-wizard`가 같은 문제를 이미 풀어놨으나 그대로 가져오면 안 되는 차이가 있다.

1. 그쪽은 커밋 컨벤션이 순수 Conventional Commits라 줄 맨 앞에 타입이 온다. 우리
   컨벤션은 줄 앞이 한글 제목이라 표준 breaking 마커 판정이 **절대 매칭되지 않는다.**
   minor 판정은 그대로 작동하지만 major만 경로가 비어 있어, 우리 컨벤션용 마커를
   함께 신설해야 한다.
2. 그쪽의 커밋 분류 함수는 릴리스 노트 렌더링까지 겸하는데, 우리는 그 일을
   `changelog_providers` 사다리가 이미 한다. 통째로 이식하면 릴리스 노트 생성 경로가
   둘로 갈라져 드리프트가 나므로, 승격 폭 판정만 하는 함수를 따로 둔다.

⚙️ 작업 내용
---

- 버전 관리 스크립트에 승격 폭 인자 추가 (기존 patch 동작은 기본값으로 보존)
- 커밋 제목으로 승격 폭을 판정하는 서브커맨드 신설
- 릴리스 워크플로우에 커밋 수집 단계와 옵션 분기 추가
  (루트와 `project-types/common/` 두 곳을 동일하게 유지)
- 마법사의 `version.yml` 옵션 파싱, 기록에 신규 옵션 반영
- 커밋 컨벤션 문서에 breaking 마커 규칙 추가
- 판정 규칙, 버전 증가 회귀 테스트 신설
