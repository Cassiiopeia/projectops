📝 현재 문제점
---

- **코드 렌더(위젯 렌더, Playwright locator 캡처)는 projectops 어디에도 기능이 없다.** `pro-figma-verify/references/rendering.md`에 설명만 있다.
- 실기기 캡처로는 **엣지 상태**(빈 목록 · 실패 · 긴 글자 · 권한 거부)를 만들기 어렵다. 서버 데이터를 건드려야 해서 느리고 위험하다.
- 2026-09-25 Twin-Fang/elum #419에서 사람이 손으로 했다. 임시 위젯 테스트 파일로 실제 화면 9장(현재 구현 + 대안 목업)을 뽑고, 파일을 치운 뒤 `git status`로 흔적을 확인했다. 과정에서 겪은 함정이 있었다.
  - 오버레이를 `Material` 밖에 그려 글자에 노란 이중 밑줄이 붙었다
  - 무한 애니메이션 때문에 `pumpAndSettle`이 끝나지 않았다
  - `dart format`이 건드리지 않은 줄까지 바꿔 diff가 커졌다

🛠️ 해결 방안 / 제안 기능
---

- `pro-launch`에 `render run` 명령과 **스택별 레시피 문서**를 넣는다.
- 원칙: **렌더 코드는 agent가 레시피를 보고 대상 레포에 임시로 짠다.** 스크립트는 실행 · 수집 · 청소 · 흔적 검사만 한다. 상태 관리 방식(Riverpod · Bloc · Redux …)을 스크립트가 알아맞히지 않는다.
- 선행: #629
- 설계: `docs/superpowers/specs/2026-09-25-pro-launch-design.md` §5.1, §6

⚙️ 작업 내용
---

**명령 `render run --cmd "<명령>" --collect <glob> [--cleanup <path>...]`**
- [ ] 실행 전 대상 레포 `git status --porcelain`을 저장한다
- [ ] 명령 실행 → 실패하면 수집하지 않고 청소만 한 뒤 `code: "render_failed"` + 출력 끝 40줄
- [ ] `--collect` 글롭의 PNG를 `$SHOT_DIR`로 옮긴다 (이름 유지, 충돌 시 번호)
- [ ] `--cleanup` 경로를 지운다
- [ ] 실행 후 `git status`가 실행 전과 다르면 `ok: false, code: "residue"` + 남은 경로를 돌려준다. **지우지 않는다** (다른 세션의 변경일 수 있다)

**`references/render.md` 레시피 (스택별: 기본 캡처 · 엣지 상태 연출 · 보조 · 함정)**
- [ ] Flutter: 위젯 테스트 + `matchesGoldenFile` 임시 경로 + `--update-goldens`. 폰트를 싣는 `flutter_test_config.dart`가 있는지 먼저 확인한다 (없으면 한글이 □). 상태 관리 override, `MediaQuery` 안전영역 재현. 함정 3개(위 elum 실측)
- [ ] React / Next: Playwright 스크린샷, Storybook이 있으면 스토리 URL을 우선. `web route`로 응답 교체, `web viewport`로 폭 변경
- [ ] React Native: `app shot` + 목 서버 / 개발 메뉴 플래그. 보조로 Expo 웹 빌드 + Playwright
