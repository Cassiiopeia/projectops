# pro-launch 컴퓨터별 학습 메모 설계

## 목표
사람마다 컴퓨터마다 잘 되는 조작 방식이 다르다. `pro-launch`가 **이 컴퓨터에서 실제로 먹힌 방법**을 기억하고,
쓸수록 더 정확해지게 한다. 단, 토큰을 아낀다: 기억을 꺼내는 비용이 작아야 하고, 헛수고(같은 실패 반복)를 줄여야 한다.

## 배경(확인한 사실)
- `~/.projectops/launch/<owner__repo>/` 가 이미 **컴퓨터별 상태 저장소**다 (`devices.json`, `browser.json`, `access.json`, `shots/`). 새 자리를 만들 필요가 없다.
- `pro-note`는 사람이 읽는 **사례 기록**(왜 막혔고 어떻게 풀었나, 프로젝트 docs 또는 홈)이다. 목적이 달라 합치지 않는다.
- 이 컴퓨터: `maestro`·`xcodebuild`·`cliclick` 설치, `idb`·`appium` 없음. `cliclick`이 깔려 있어 에이전트가 좌표 클릭을 택할 수 있었다.
- 실사고(#640): iOS 시뮬레이터를 호스트 마우스 좌표로 눌러 사용자 커서가 움직였다. 금지 규칙은 이미 반영(fix, 푸시 완료).

## 기존 기억 장치와의 경계 (구현 전 확인)
| 장치 | 무엇을 쌓나 | 위치 |
|---|---|---|
| `pro-agent-test` `e2e_cli.py note` (`learned.json`) | **테스트 대상 앱**의 화면·좌표·함정·제약 | `~/.projectops/agent-test/<repo>/` |
| `pro-note` | 사람이 읽는 사례(왜 막혔고 어떻게 풀었나) | 프로젝트 docs 또는 홈 |
| **새 `launch_cli recall/learn`** | **이 컴퓨터·도구 차원**: 어떤 조작 방식이 먹혔나(iOS는 Maestro, Google 로그인은 `--headed` 등) | `~/.projectops/launch/...` |

앱 화면 지식은 `note`에 그대로 둔다(중복 저장 금지). 새 장치는 앱이 아니라 **도구·방식**만 다룬다.

## 설계

### 저장
| 파일 | 범위 | 예 |
|---|---|---|
| `~/.projectops/launch/<owner__repo>/knowledge.json` | 이 레포 + 이 컴퓨터 | "iOS는 `client/tool/e2e_shot.sh`(Maestro)로 돈다" |
| `~/.projectops/launch/_machine/knowledge.json` | 이 컴퓨터 전체 | "Google 로그인은 `--headed`여야 통과" |

커밋·공유되지 않는다(홈 디렉터리). 값은 짧은 사실만: 비밀번호·토큰·쿠키는 저장하지 않는다(기존 scrub 규칙 재사용).

### 항목 스키마
`{key, area(ios|android|web|server), how, ok, fail, last_seen, note?}`
- `key`: 정규화한 한 줄(예: `ios.tap`). 같은 key는 갱신(중복 누적 금지).
- **강화 = 카운터.** 성공을 보고하면 `ok+1`, 실패하면 `fail+1`. 꺼낼 때 `ok-fail` 순으로 정렬한다.
- `fail > ok`인 항목은 "믿지 말고 한 번 확인" 표시로 내려가고, 오래 안 쓰이면(`last_seen` 90일) 뒤로 밀린다.
- 항목 수 상한 30개(범위별). 넘으면 점수 낮은 것부터 지운다 → 파일이 무한히 커지지 않는다.

### CLI (launch_cli.py, 표준 JSON + next)
- `recall --area ios [--limit 5]` : 상위 항목만 돌려준다 (**기본 5개, 항목당 200자 이내** — 한 번 호출이 수백 토큰).
- `learn --area ios --key ios.tap --how "..." --result ok|fail` : upsert + 카운터 갱신. 비밀값 패턴이 보이면 거절.
- `forget --key ...` : 잘못 배운 것 삭제.

### 스킬 절차 (SKILL.md 짧게 추가)
1. 앱·웹 작업 **시작 시 `recall` 한 번** — 이 컴퓨터에서 먹힌 방법을 먼저 쓴다.
2. 작업 **끝에 `learn`** — 처음 알게 된 것, 또는 기억이 맞았는지/틀렸는지 결과만.
3. 사례가 복잡하면(왜 실패했는지 설명이 필요) `pro-note`를 권한다. 학습 메모에는 결론만 남긴다.

### 안전 규칙이 기억보다 위다
금지 규칙(#640 좌표 클릭 금지, 자격증명 규칙)은 **학습 메모가 뒤집을 수 없다.** 메모는 "허용된 방법 사이의 우선순위"만 정한다.
"이 컴퓨터에서는 cliclick이 잘 된다" 같은 항목이 들어와도 recall은 금지된 방법이면 걸러서 내보낸다.

## 토큰 절약 원칙 (함께 적용)
- 화면 이미지를 읽는 것이 가장 비싸다. **텍스트로 확인할 수 있으면(assertVisible, 계층 덤프, 로그) 스크린샷을 읽지 않는다.**
- 캡처는 기본 긴 변 1200px WebP(기존 `shrink`) 유지, 필요할 때만 원본.
- 한 번 만든 E2E 플로우 경로는 학습 메모에 저장해 다시 짜지 않는다. (스크린샷→판독→좌표→조작 루프는 단계마다 이미지를 읽어 가장 많이 든다.)
- recall/learn 출력은 항상 짧은 JSON, 긴 로그는 파일 경로만 돌려준다.

## 영향도
| 대상 | 변경 |
|---|---|
| `skills/pro-launch/scripts/` | 새 모듈 `knowledge.py`, `launch_cli.py`에 서브커맨드 3개 |
| `skills/pro-launch/tests/` | 카운터·정렬·상한·비밀값 거절·금지 방법 필터·동시 쓰기 테스트 |
| `skills/pro-launch/SKILL.md`, `references/app.md`·`web.md` | 절차 몇 줄, 서브커맨드 표, 저장 위치 표 |
| `CLAUDE.md`(프로젝트) | launch 서브커맨드 목록에 `recall, learn, forget` 추가 |
| 배포·워크플로우·`version.yml` | 변경 없음. 릴리스 타입 `feat`(minor) |
| 사용자 컴퓨터 | 로컬 파일만 생성. 기존 사용자는 파일이 없어도 그대로 동작(없으면 빈 결과) |

## 위험과 대응
- **틀린 기억이 굳는다** → `fail` 카운터, "한 번 확인" 표시, 90일 감쇠, `forget`.
- **여러 세션이 동시에 쓴다** → 임시 파일에 쓰고 교체(원자적 저장), 읽기 실패 시 빈 메모로 계속 진행(작업을 막지 않는다).
- **비밀값 유입** → `learn`에서 토큰·비밀번호 패턴 거절 + 저장 전 scrub.
- **기억이 안전 규칙을 우회** → 위 "안전 규칙이 기억보다 위" 필터 + 테스트로 고정.

## 열린 결정 (기본값 제안)
1. 저장 범위: 레포별 + 컴퓨터 전체 둘 다 (제안). 단순화하려면 레포별만.
2. 기록 시점: 에이전트가 끝에 `learn`을 명시 호출 (제안). CLI가 몰래 자동 기록하지는 않는다 — 무엇이 남는지 눈에 보이게.
