# 스킬 하네스 공통 패턴

> 근거: 2026-10 세션 기록 감사(약 770개 세션, 1·2차 pro-launch 감사 포함). 이슈 #950.

## 목적
스킬 하네스를 더 잘 만들기 위해, 세션 감사에서 반복 확인된 **스킬에 무관한 일반 교훈**을 모은다. 오픈소스 공유와 다른 하네스 적용의 기준 문서로 쓴다. 개별 버그는 연결된 이슈에서 다루고 여기서는 패턴만 다룬다.

## 잘 되는 것 (유지하고 일반화)
- 균일한 JSON 봉투(`ok`, `code`, `summary`, `next`): 약 3,360회 호출 중 `ok:false`는 약 90건이고 전부 기계가 읽을 수 있었다. 에이전트가 문구가 아니라 `code`로 분기하고 `next`를 따라간다.
- `bad_args`를 JSON으로: 한 턴에 자가 수정. `available_subcommands`가 쓰인다.
- 도메인을 아는 경고: `label_warning`, `assignee_warning`, 한글/영문 상태 라벨 동치(#776).
- 환경변수로 비밀 전달(`SECRET_VALUE`), `sanitize-message`, 경로를 명시한 스테이징, 리다이렉트 안전한 로그 다운로드.
- pro-launch의 고정 진입점 + `newer_installed`, `known_fix`와 `kb`, `learn_hint`, 기기 점유(claim) 표시.
- 원격 저장소를 바꾸는 작업의 dry-run `before/planned` + 레포별 승인.

## 일반 교훈
1. **에이전트는 인자, 정규식, 키 이름을 추측한다.** 가장 많이 추측되는 형태를 받아 주거나 힌트와 함께 실패시킨다. 같은 추측이 독립 세션에서 반복되면 제품 신호다 (`--issue N`은 약 12개 세션).
2. **사용법을 구조화된 오류 안에 넣는다.** `usage`, 예시 1개, 가장 가까운 서브커맨드. 에이전트는 stdout JSON만 읽는다.
3. **고정 진입점이 경로 탐색을 이긴다.** 호출의 18%가 `find | sort -V | tail -1`이었다.
4. **필드 선택자와 출력 스키마를 제공한다.** `--field a.b`가 인라인 Python과 KeyError 계열을 없앤다.
5. **검증된 원시 API 탈출구를 둔다.** 기능이 비면 에이전트는 설정 파일에서 토큰을 읽어 curl을 쓴다. 인증을 중앙에서 주입하는 `api` 통과 명령이 더 안전하다. 세션에서 `api.github.com`을 grep하면 부족한 기능 지도가 나온다.
6. **폴링은 도구 안에 둔다.** `--wait --timeout` 한 번이 `sleep`(하네스가 차단), 예약 깨우기, 감시 루프보다 낫다. 종결 verdict와 `next`를 돌려준다.
7. **대기 상태에는 나이와 탈출구가 있어야 한다.** 시간 제한 없는 `waiting`은 죽은 파이프라인을 무한 대기로 만든다 (4.5시간). `age_seconds`를 싣고 임계값에서 `stuck`.
8. **에이전트가 3번 넘게 손으로 치는 의식은 서브커맨드로 만든다.** base 동기화, worktree 생성+복사+기록, 댓글+라벨+닫기.
9. **일시적 오류와 영구 오류를 분리한다.** 5xx만 재시도하고 `retryable`을 표시한다. 멱등이 아닌 호출은 마커로 중복을 감지한다.
10. **값싼 전제조건은 도구 안에서 먼저 확인한다.** 브랜치가 origin에 있는지 확인하면 GitHub의 모호한 422 대신 원인 이름이 나온다.
11. **비밀을 argv로 받지 않는다.** 권한 분류기가 막으면 에이전트는 방법을 바꾸지 않고 포기한다. 저장소, 환경변수, 사람용 프롬프트를 제공한다. 비밀을 읽으라는 문서 안내도 세션 기록에 새어 나간다.
12. **조용한 보정은 버그다.** 이미지 리사이즈, 빈 입력 수용, `Path('.').parents`. 구조화된 경고로 드러낸다.
13. **전송 성공과 원격 명령 실패를 구분한다.** ssh 255, sshpass 5 같은 알려진 종료 코드를 이름 있는 code로 옮기고, 원격 출력은 바이트로 받아 utf-8 > 레거시 코드페이지 > replace 순으로 해석한다.
14. **환경을 바꾸는 QA 단계는 장부를 남긴다.** 이전/이후 값을 기록하고 복원을 검증한다. 결함을 올리기 전에 잔여 상태와 도구 오류를 다른 입력 경로로 배제한다.
15. **플랫폼 대칭 표를 문서화한다.** 한쪽만 있는 표는 에이전트가 반대쪽을 손으로 만들게 한다 (Maestro YAML 22개). 만들 수 없으면 조용히 건너뛰지 말고 `blocked`와 이유.
16. **큰 페이로드는 파일 기반 happy path를 둔다.** MCP 결과가 큰 도구는 하네스가 저장한 결과 파일을 받는 `ingest`가 없으면 에이전트가 토큰을 다시 쓰거나 도구를 건너뛴다.
17. **서브에이전트 계약**: 작업자가 자기 출력 파일을 쓰고 검증하며, 부모는 존재만 확인한다. 해결된 스크립트 경로를 프롬프트 틀에 넣는다.
18. **승인 게이트를 구분한다.** "보고서 쓰기"는 자동일 수 있고 "원격 저장소 변경"은 항상 수동이며 변경 전후 값을 보여 준다.
19. **결정적 선택은 스크립트로 제공한다.** "가장 약한 3개"를 산문으로 두면 실행마다 답이 다르다.
20. **사용량 계측으로 죽은 기능을 찾는다.** 서브커맨드와 code만(인자 제외) 로컬에 기록하고 릴리스마다 "한 번도 안 불린 것", "가장 흔한 오류 code", `--help` 호출 수, raw API 호스트, 탐색 보일러플레이트 수를 본다. 이 네 숫자만으로 이번 감사의 대부분이 나왔다.
21. **문서와 코드는 양쪽 OS에서 문서 그대로 실행하는 테스트로 묶는다.** Windows에서만 검증한 레시피가 macOS에서 조용히 깨진다. 텍스트를 자르는 git 포슬린 같은 금지 관용구는 린트로 막는다.
22. **모델/노력 적합성을 데이터로.** 산문 배너(`⚠️ 모델 권고`) 대신 frontmatter 필드. 병렬 작업자는 사용한 모델을 출력에 기록하고 퇴화 출력(예: 인용 0건)에 경고한다.
23. **실패 응답에 해결 id를 싣는다.** 세션에서 검증된 해결을 3번 실패한 뒤가 아니라 첫 실패에서 보여 준다.
24. **사실 기억에는 실패와 미지원 플랫폼 탐색도 남긴다.** 안 그러면 매 세션이 `chcp`, `schtasks`를 다시 배운다.
